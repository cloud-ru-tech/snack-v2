# Locale

Пакет предоставляет контекст локализации для приложения: `LocaleProvider`, хук `useLocale` и фабрику `createLocaleContext`. Поддерживаются вложенные ключи вида `Component.key.subkey`, интерполяция плейсхолдеров `{{name}}` и расширение словарей. В комплекте идут локали `en-GB` и `ru-RU` с базовым набором строк.

## Overview

- **LocaleProvider** — провайдер контекста: задаёт язык (`lang`), опциональный запасной язык (`fallbackLang`) и переопределение локалей (`overrideLocales`).
- **useLocale** — хук возвращает функцию перевода `t(key, interpolation?)` и текущий `lang`. Можно вызывать без аргументов (доступ ко всем ключам) или с именем «компонента» для ограничения ключей типом.
- **createLocaleContext** — создаёт отдельный контекст с расширенным словарём (`extendedDictionary`) и своим `defaultLanguage`, полезно для приложений со своими переводами поверх базовых.
- **Встроенные локали** — `LOCALES` и константа `DEFAULT_LANG` (`'en-GB'`). Ключи переводов типизированы через точечную нотацию (`Common.apply`, `Common.cancel` и т.д.).
- **Интерполяция** — в строках перевода плейсхолдеры `{{key}}` подставляются из второго аргумента `t(key, { key: value })`.

## Usage

### Базовое использование

Оберните приложение в `LocaleProvider`, передайте текущий язык. В дочерних компонентах используйте `useLocale()` для доступа к `t` и `lang`.

```tsx
import { LocaleProvider, useLocale } from '@design-system/locale';

function TranslatedButton() {
  const { t, lang } = useLocale();
  return (
    <button>
      {t('Common.apply')} ({lang})
    </button>
  );
}

export function App() {
  return (
    <LocaleProvider lang="en-GB">
      <TranslatedButton />
    </LocaleProvider>
  );
}
```

### Смена языка и fallback

При неизвестном `lang` используется `fallbackLang` (по умолчанию — `DEFAULT_LANG`), в консоль выводится предупреждение.

```tsx
import { LocaleProvider } from '@design-system/locale';

function App() {
  return (
    <LocaleProvider lang="ru-RU" fallbackLang="en-GB">
      <Content />
    </LocaleProvider>
  );
}
```

### Интерполяция в переводах

Второй аргумент `t` — объект подстановки. В строке перевода плейсхолдеры `{{name}}` заменяются на значения; если значения нет или пустая строка, плейсхолдер остаётся как есть.

```tsx
const { t } = useLocale();
// При строке в локали: "Hello, {{who}}!"
t('Some.greeting', { who: 'World' }); // "Hello, World!"
```

### Ограничение ключей по «компоненту»

Если передать в `useLocale` имя ключа верхнего уровня (например, `'Common'`), то `t` будет принимать только ключи внутри этого блока — удобно для типизации и автодополнения в компонентах.

```tsx
const { t } = useLocale('Common');
t('apply');   // ключ относительно Common
t('cancel');
```

### Переопределение локалей

Через `overrideLocales` можно подменить часть переводов без изменения исходных словарей (например, кастомные формулировки для продукта).

```tsx
<LocaleProvider
  lang="en-GB"
  overrideLocales={{
    'en-GB': {
      Common: {
        apply: 'Submit',
        cancel: 'Discard',
      },
    },
  }}
>
  <App />
</LocaleProvider>
```

### Расширенный контекст (createLocaleContext)

Для приложения со своими переводами создайте отдельный контекст с расширенным словарём и используйте возвращённые `LocaleProvider` и `useLocale`.

```tsx
import { createLocaleContext } from '@design-system/locale';

const myLocales = {
  'en-GB': { MyBlock: { title: 'Title' } },
  'ru-RU': { MyBlock: { title: 'Заголовок' } },
};

const { LocaleProvider, useLocale } = createLocaleContext({
  extendedDictionary: myLocales,
  defaultLanguage: 'en-GB',
});

function App() {
  return (
    <LocaleProvider lang="en-GB">
      <Content />
    </LocaleProvider>
  );
}
```

## Экспорты и типы

Из пакета экспортируются:

- **Компоненты и контекст:** `LocaleProvider`, `useLocale`, `createLocaleContext`
- **Типы:** `LocaleProviderProps`, `LocaleLang`, `LocaleDictionary`, `Locales`, `OverrideLocales`, `DottedTranslationKey`, `Dictionary`, `TranslatedEntity`, `InterpolationObject`, `ExtendedDictionary`
- **Данные:** `LOCALES`, `DEFAULT_LANG` (`'en-GB'`)

Тип ключа перевода `DottedTranslationKey` строится по структуре словаря: допустимы точечные пути до строк (например, `'Common.apply'`).

## Accessibility

Провайдер не рендерит свою разметку и не влияет на доступность напрямую. Следите за тем, чтобы переведённые строки (кнопки, подписи, `aria-label`) были осмысленными для скринридеров и соответствовали выбранному языку.

## Best practices

1. **Один провайдер на дерево** — оборачивайте корень приложения или нужную область в один `LocaleProvider`; при смене языка обновляйте проп `lang`.
2. **Fallback** — задавайте `fallbackLang` при поддержке не всех языков из `LOCALES`, чтобы при ошибочном `lang` интерфейс оставался на читаемом языке.
3. **Расширение словарей** — для больших приложений используйте `createLocaleContext` с `extendedDictionary`, чтобы сохранить типизацию и не смешивать базовые и продуктовые ключи.
4. **Интерполяция** — используйте плейсхолдеры `{{key}}` в строках локалей и передавайте значения вторым аргументом `t(key, object)` для динамических подстановок.
