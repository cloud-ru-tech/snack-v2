# WithSkeleton

Обёртка для условного отображения скелетона или контента. При `loading={true}` отображается `skeleton`, при `loading={false}` — `children`. Позволяет задать произвольный JSX скелетона (Skeleton, SkeletonText или композицию).

```tsx
import { WithSkeleton, SkeletonText } from '@design-system/skeleton';

<WithSkeleton
  loading={isLoading}
  skeleton={<SkeletonText loading width={200} />}
>
  <span>Контент после загрузки</span>
</WithSkeleton>
```

### Композиция скелетона

Можно передать произвольный JSX — несколько Skeleton и SkeletonText:

<ExampleContainer>
  <ExampleRow gap="large" justifyContent="flex-start">
    <ExampleItem label="Карточка">
      <WithSkeletonCompositionExample />
    </ExampleItem>
  </ExampleRow>
</ExampleContainer>

```tsx
import { WithSkeleton, Skeleton, SkeletonText } from '@design-system/skeleton';

<WithSkeleton
  loading={true}
  skeleton={
    <div style={{ display: 'flex', flexDirection: 'column', gap: 12 }}>
      <Skeleton loading width={48} height={48} borderRadius="50%" />
      <SkeletonText loading lines={2} purpose="body" size="m" width={180} />
      <Skeleton loading width={120} height={32} borderRadius={4} />
    </div>
  }
>
  <div>Карточка пользователя</div>
</WithSkeleton>
```

## Accessibility

- При `loading={true}` для скринридеров желательно добавить `aria-busy="true"` на родительский контейнер или текст «Загрузка…».
- Контент в `children` должен быть семантически корректным после загрузки.

## Best practices

1. **Соответствие контенту** — скелетон должен визуально повторять структуру загружаемого контента.
2. **Переиспользование** — выносите композиции скелетонов в отдельные компоненты при частом использовании.
3. **Управление loading** — флаг `loading` обычно приходит из хука загрузки данных (useQuery, useEffect и т.п.).
