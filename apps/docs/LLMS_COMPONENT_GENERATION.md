# LLM.txt Generation for Components

This document describes how LLM.txt files are automatically generated for each component in the design system.

## Overview

The documentation system automatically generates three types of LLM.txt files:

1. **llms-components.txt** - All component documentation combined
2. **llms-guides.txt** - All guides and tutorials combined
3. **Individual component files** - Separate LLM.txt for each component (e.g., `llm-avatar.txt`)

## Architecture

### Main Integration: starlight-llms-txt

Configured in `astro.config.mjs`:

```typescript
starlightLlmsTxt({
  projectName: 'Design System',
  rawContent: true,
  customSets: [
    {
      label: 'components',
      paths: ['components/**'],
    },
    {
      label: 'guides',
      paths: ['guides/**'],
    },
  ],
})
```

This generates:
- `llms-components.txt` - includes all files matching `components/**`
- `llms-guides.txt` - includes all files matching `guides/**`

### Custom Integration: generate-component-llms

Located in `src/integrations/generate-component-llms.ts`

This integration:
1. Scans all component directories in `src/content/docs/en/components/`
2. For each component, generates `llm-{component-name}.txt`
3. Strips MDX-specific elements (imports, JSX components)
4. Preserves markdown content and code examples
5. Adds UTF-8 BOM for proper encoding
6. Creates an index file listing all component-specific files

Output location: `dist/_llms-txt/components/`

Files generated:
- `llm-avatar.txt`
- `llm-button.txt`
- `llm-{component}.txt`
- `index.txt` - index of all component files

### Encoding Fix: fixLlmsEncoding

Located in `src/integrations/fixLlmsEncoding.ts`

This integration runs after build to ensure proper UTF-8 encoding for all LLM.txt files:
- Adds UTF-8 BOM (`\uFEFF`)
- Normalizes line endings to `\n`
- Ensures consistent encoding across all generated files

## Using LlmLink Component in Documentation

### Import and Usage

In your component documentation MDX file:

```mdx
import LlmLink from '../../../../../components/LlmLink.astro';

<LlmLink component="component-name" />
```

### Component Props

- `component` (required) - The component name matching the directory name

The component automatically:
1. Shows a title and description
2. Displays a button to open the LLM.txt file
3. Provides a copy button to copy the full URL
4. Shows the explicit file path for reference
5. Opens in a new tab when clicked

### Placement

Place the `<LlmLink>` component after the Changelog section:

```mdx
## Changelog

import Changelog from '../../../../../components/Changelog.astro';

<Changelog packageName="component-name" />

## LLM Documentation

import LlmLink from '../../../../../components/LlmLink.astro';

<LlmLink component="component-name" />

## Overview
```

### Component Features

The LlmLink component displays:

1. **Header** - "LLM-оптимизированная документация" with icon
2. **Description** - Explains what the file is for
3. **Open button** - Opens the LLM.txt file in a new tab
4. **Copy button** - Copies the full URL to clipboard (with visual feedback)
5. **Explicit URL** - Shows the file path as code: `/_llms-txt/components/llm-{component}.txt`

This makes it easy for users to:
- Quickly access the LLM.txt file
- Copy the direct link to share or use in AI tools
- See the exact file location

## Template

Use `COMPONENT_DOC_TEMPLATE.mdx` when creating new component documentation. It includes:

1. Proper frontmatter structure
2. Changelog integration
3. **LlmLink component pre-configured**
4. Standard sections structure
5. Example imports and usage

## Build Process

### Development

```bash
pnpm dev
```

LLM.txt files are not generated during development.

### Production Build

```bash
pnpm build
```

Build process:
1. Astro builds the site
2. `starlight-llms-txt` generates `llms-components.txt` and `llms-guides.txt`
3. `generate-component-llms` generates individual component files
4. `fixLlmsEncoding` ensures proper UTF-8 encoding for all files

### Output Structure

```
dist/
├── llms.txt                    # Main index (generated by starlight)
├── llms-full.txt               # Full documentation (generated by starlight)
├── llms-small.txt              # Minimal version (generated by starlight)
├── llms-components.txt         # All components (generated by starlight)
├── llms-guides.txt             # All guides (generated by starlight)
└── _llms-txt/
    ├── llms-components.txt     # Alternative location
    ├── llms-guides.txt         # Alternative location
    └── components/
        ├── index.txt           # Index of all component files
        ├── llm-avatar.txt      # Avatar component
        ├── llm-button.txt      # Button component
        └── llm-{name}.txt      # Other components
```

## Content Processing

### What Gets Included

- Frontmatter metadata (title, description)
- Markdown content
- Code blocks
- Heading structure
- Lists and tables

### What Gets Removed

- Import statements
- JSX comments
- Interactive components (`ExampleContainer`, `ExampleRow`, etc.)
- Storybook iframes
- Other MDX-specific elements

### Encoding

All files are generated with:
- UTF-8 encoding with BOM (`\uFEFF`)
- Unix line endings (`\n`)
- Proper Unicode character support

## Accessing LLM.txt Files

### Component-Specific Files

```
https://your-site.com/_llms-txt/components/llm-avatar.txt
https://your-site.com/_llms-txt/components/llm-button.txt
```

### Combined Files

```
https://your-site.com/llms-components.txt
https://your-site.com/llms-guides.txt
https://your-site.com/llms.txt
```

### Index

```
https://your-site.com/_llms-txt/components/index.txt
```

## Troubleshooting

### Files Not Generated

1. Check that `starlight-llms-txt` is installed:
   ```bash
   pnpm list starlight-llms-txt
   ```

2. Verify integration is enabled in `astro.config.mjs`

3. Check component directory structure matches pattern

4. Look for build errors in console

### Encoding Issues

The `fixLlmsEncoding` integration should handle encoding automatically.

If issues persist:
1. Check file encoding with: `file -I filename.txt`
2. Verify BOM is present: `hexdump -C filename.txt | head`
3. Check integration order in `astro.config.mjs`

### Missing Content

If content is missing from generated files:
1. Check MDX file has proper frontmatter
2. Verify content isn't being filtered by content processing rules
3. Review integration console output during build
