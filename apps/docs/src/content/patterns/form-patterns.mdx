# Form Patterns

Forms are the primary surface through which users submit structured input. These patterns apply across the design system.

## Submit and Cancel

Always provide a clear exit path. The submit action is `primary`; the cancel is `ghost` or `secondary`:

```tsx
<form onSubmit={handleSubmit}>
  {/* fields */}
  <div style={{ display: 'flex', gap: '0.5rem', justifyContent: 'flex-end' }}>
    <Button variant="ghost" type="button" onClick={onCancel}>
      Cancel
    </Button>
    <Button variant="primary" type="submit" loading={isSubmitting}>
      Save changes
    </Button>
  </div>
</form>
```

## Inline Confirmation

For actions that are immediate (no dialog), place confirmation inline:

```tsx
<Button variant="danger" onClick={handleDelete}>
  Delete
</Button>
```

Only use an inline danger button when the action is clearly scoped (e.g. deleting a single row). For irreversible operations that affect a lot of data, use a confirmation dialog instead — see [Composition Patterns](/patterns/composition-patterns).

## Field Layout

- Stack fields vertically with consistent spacing (`--space-4` between fields).
- Group related fields in a `<fieldset>` with a `<legend>`.
- Put the submit group at the bottom, separated by extra space (`--space-8`).
