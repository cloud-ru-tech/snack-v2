# Composition Patterns

These patterns describe how to arrange multiple design system components together so that interfaces feel consistent, accessible, and intentional.

## Action Groups

When a surface has multiple actions, group them together. Place the primary action last (rightmost in LTR layouts):

```tsx
<div style={{ display: 'flex', gap: '0.5rem', justifyContent: 'flex-end' }}>
  <Button variant="ghost">Cancel</Button>
  <Button variant="secondary">Save draft</Button>
  <Button variant="primary">Publish</Button>
</div>
```

**Rules:**
- Never more than one `primary` button in a group.
- Maximum three actions before reaching for a dropdown menu.
- Destructive actions (`danger` variant) should be separated from the group or placed furthest from the primary.

## Confirmation Dialogs

Dialogs that confirm destructive operations require:
1. A clear, action-labelled primary button (e.g. "Delete project", not "OK")
2. A ghost or secondary cancel action
3. The destructive button uses the `danger` variant

```tsx
<Button variant="ghost" onClick={onCancel}>Keep project</Button>
<Button variant="danger" onClick={onConfirm}>Delete project</Button>
```

## Loading States

When a form submits, disable and show a loading state on the submit button only — not the cancel:

```tsx
<Button variant="ghost" disabled={isLoading}>Cancel</Button>
<Button variant="primary" loading={isLoading}>Save changes</Button>
```
