# Анализ реализации генерации llms.txt файлов

## Текущая реализация в проекте

### Компоненты системы

1. **Плагин `starlight-llms-txt` (v0.6.0)**
   - Генерирует llms.txt файлы из контента документации
   - Поддерживает кастомные наборы файлов (customSets)
   - Интегрируется как плагин Starlight

2. **Кастомная интеграция `fixLlmsEncoding`**
   - Расположение: `src/integrations/fixLlmsEncoding.ts`
   - Назначение: исправление кодировки сгенерированных файлов
   - Функции:
     - Нормализация окончаний строк (CRLF → LF)
     - Добавление UTF-8 BOM для явной маркировки кодировки
     - Обработка всех сгенерированных llms.txt файлов

### Конфигурация

**Файл:** `astro.config.mjs`

**Ключевые настройки:**

```javascript
starlightLlmsTxt({
  projectName: "Дизайн паттерны",
  exclude: ["design/**"],           // Исключение страниц с React компонентами
  rawContent: true,                  // Использование сырого контента
  customSets: [
    {
      label: "llms-coding",         // Создает llms-coding.txt
      paths: [
        "global/code-style/**",
        "global/i18n/**",
        "global/metrics/**",
        "global/routing/**",
        "global/adaptive/**",
      ],
    },
    {
      label: "llms-devflow",        // Создает llms-devflow.txt
      paths: [
        "global/development-flow/**",
        "global/git-flow/**",
        "global/ci-cd/**",
        "global/gitlab-structure/**",
      ],
    },
  ],
})
```

### Генерируемые файлы

После сборки (`pnpm build`) создаются следующие файлы в `dist/`:

- `llms.txt` — полный индекс документации
- `llms-full.txt` — полная версия документации
- `llms-small.txt` — сокращенная версия
- `llms-coding.txt` — специализированный файл для coding-агентов
- `llms-devflow.txt` — руководство по процессам разработки
- `_llms-txt/llms-coding.txt` — альтернативное расположение
- `_llms-txt/llms-devflow.txt` — альтернативное расположение

### Структура контента

Плагин сканирует контент из `src/content/docs/`:

```
src/content/docs/
├── global/
│   ├── code-style/      → llms-coding.txt
│   ├── i18n/            → llms-coding.txt
│   ├── metrics/         → llms-coding.txt
│   ├── routing/         → llms-coding.txt
│   ├── adaptive/        → llms-coding.txt
│   ├── development-flow/ → llms-devflow.txt
│   ├── git-flow/        → llms-devflow.txt
│   ├── ci-cd/           → llms-devflow.txt
│   └── gitlab-structure/ → llms-devflow.txt
└── design/              → исключено через exclude
```

### Жизненный цикл генерации

1. **Сборка Astro** (`pnpm build`)
   - Starlight обрабатывает контент
   - Плагин `starlight-llms-txt` генерирует llms.txt файлы
   - Файлы сохраняются в `dist/`

2. **Хук `astro:build:done`**
   - Интеграция `fixLlmsEncoding` срабатывает после завершения сборки
   - Обрабатывает все сгенерированные llms.txt файлы
   - Нормализует кодировку и добавляет BOM

### Зависимости

```json
{
  "devDependencies": {
    "starlight-llms-txt": "0.6.0"
  }
}
```

## Ключевые особенности реализации

### 1. Использование rawContent

```javascript
rawContent: true
```

**Причина:** Предотвращает попытки рендерить React компоненты в текстовый файл. Используется сырой markdown контент.

### 2. Исключение страниц

```javascript
exclude: ["design/**"]
```

**Причина:** Страницы дизайна содержат интерактивные React компоненты, которые не должны попадать в llms.txt файлы.

### 3. Кастомные наборы (customSets)

Позволяют создавать специализированные llms.txt файлы для разных целей:
- `llms-coding.txt` — для coding-агентов
- `llms-devflow.txt` — для вопросов о процессах разработки

### 4. Исправление кодировки

Интеграция `fixLlmsEncoding` решает проблему:
- Некорректной кодировки файлов на разных платформах
- Смешанных окончаний строк (CRLF/LF)
- Отсутствия явной маркировки UTF-8 (BOM)

## Перенос в другой репозиторий

### Необходимые файлы

1. `src/integrations/fixLlmsEncoding.ts` — интеграция для исправления кодировки
2. Изменения в `astro.config.mjs`:
   - Импорты плагина и интеграции
   - Подключение интеграции
   - Конфигурация плагина в starlight.plugins

### Адаптация под другой проект

1. **Изменить `projectName`** под название нового проекта
2. **Адаптировать `exclude`** под структуру документации
3. **Настроить `customSets.paths`** под реальную структуру контента
4. **Обновить список файлов в `fixLlmsEncoding`** если используются другие customSets

### Документация для переноса

Созданы три файла с инструкциями:

1. **LLMS_TXT_SETUP_GUIDE.md** — подробная инструкция с примерами
2. **LLMS_TXT_QUICK_START.md** — быстрый старт для опытных разработчиков
3. **LLMS_TXT_AI_PROMPT.md** — промпт для автоматической настройки через AI-агента

## Технические детали

### Хук интеграции

```typescript
'astro:build:done': async ({ dir }) => {
  // dir.pathname содержит путь к директории dist/
  // Обрабатываем все сгенерированные llms.txt файлы
}
```

### Обработка файлов

1. Проверка существования файла
2. Чтение в UTF-8
3. Удаление существующего BOM (если есть)
4. Нормализация окончаний строк
5. Добавление UTF-8 BOM
6. Запись обратно

### Обработка ошибок

- Игнорирование отсутствующих файлов (ENOENT)
- Логирование успешной обработки
- Предупреждения для других ошибок

## Рекомендации

1. **Всегда используйте `rawContent: true`** если в документации есть React компоненты
2. **Исключайте интерактивные страницы** через `exclude`
3. **Используйте customSets** для создания специализированных файлов
4. **Проверяйте кодировку** сгенерированных файлов после переноса
5. **Адаптируйте пути** под структуру конкретного проекта
