# Modal

Модальное окно для подтверждений, форм и важных сообщений. Компонент **Modal** собирает шапку (изображение, заголовок, подзаголовок, кнопка «назад», слот рядом с заголовком), прокручиваемое тело и опциональный футер. Полный контроль над разметкой — через **ModalCustom** и `ModalCustom.Header` / `Body` / `Footer`.

## Overview

**Modal** строится поверх **ModalCustom**: окно рендерится через `createPortal` (по умолчанию в `document.body` или в узел из `PortalContextProvider` пакета `@design-system/portal-context`). Пока `open={false}`, в DOM ничего не монтируется.

Компонент обеспечивает:

- **Режимы закрытия (`mode`)** — `regular`: клик по затемнению, **Escape** и кнопка закрытия; `aggressive`: только кнопка (подложка с размытием по макету Figma); `forced`: без кнопки закрытия и без закрытия по подложке/Escape (критичные сценарии).
- **Размеры** — пресеты `'s' | 'm' | 'l'` (`SIZE` в пакете), высота по контенту или ограничение по контейнеру через `heightAuto`.
- **Состояние загрузки** — при `loading` в теле показывается спиннер или произвольный `loadingState`, футер скрывается.
- **Интеграция с историей** — опционально `closeOnPopstate` (через `useModalOpenState` из `@design-system/utils`, как у других оверлеев дизайн-системы).
- **Ловушка фокуса** — при открытии фокус ставится на **контейнер диалога** (`tabIndex={-1}`), без автофокуса на кнопки (удобно при открытии мышью); первый **Tab** ведёт к первому tabbable внутри окна, **Shift+Tab** с контейнера — к последнему. **Tab** / **Shift+Tab** дальше циклически ходят только по элементам окна; после закрытия фокус возвращается на элемент, который был активен до открытия.
- **Блокировка скролла страницы** — пока окно открыто, прокрутка документа под оверлеем отключена (библиотека `react-remove-scroll`, как в Radix Dialog): колесо мыши и тач не сдвигают фон, полоса прокрутки учитывается без сдвига вёрстки; прокрутка **внутри** тела модалки (`Body` / `Scroll`) сохраняется.

### Фокус и несколько модалок

Если одновременно открыты две и более модалки, каждая монтируется отдельным порталом (обычно соседние узлы у контейнера портала): **Tab** обрабатывает только та модалка, в DOM-дереве которой сейчас находится фокус. 

`react-remove-scroll` корректно обрабатывает вложенные экземпляры: скролл документа остаётся заблокированным, пока открыта хотя бы одна модалка.

Ниже — тот же сценарий в коде: кнопка открытия, контролируемые `open` / `onClose`, шапка с изображением и футер с `ButtonGroup`.

```tsx
import { Button, ButtonGroup } from '@design-system/button';
import { Modal } from '@design-system/modal';
import { useState } from 'react';

export function Example() {
  const [open, setOpen] = useState(false);
  const close = () => setOpen(false);

  return (
    <>
      <Button appearance='primary' label='Открыть модальное окно' view='filled' onClick={() => setOpen(true)} />
      <Modal
        open={open}
        onClose={close}
        title='Заголовок'
        subtitle='Краткое описание действия или контекста'
        media={
          <img
            alt='Иллюстрация в шапке'
            className={styles.image}
            src={imageSrc(exampleHeaderImage as string | { src: string })}
          />
        }
        content={<p>Основной контент: форма, предупреждение или поясняющий текст.</p>}
        footer={
          <ButtonGroup
            primaryAction={{ label: 'Продолжить', view: 'filled', onClick: close }}
            secondaryAction={{ label: 'Отмена', appearance: 'neutral', view: 'outline', onClick: close }}
          />
        }
      />
    </>
  );
}
```

## Usage

### Базовый пример

```tsx
import { Modal } from '@design-system/modal';
import { useState } from 'react';

export function Example() {
  const [open, setOpen] = useState(false);

  return (
    <>
      <button type='button' onClick={() => setOpen(true)}>
        Открыть
      </button>
      <Modal
        open={open}
        onClose={() => setOpen(false)}
        title='Заголовок'
        content={<p>Контент</p>}
      />
    </>
  );
}
```

### С футером и кнопкой «назад»

Передайте `footer` с действиями (например, группу кнопок из `@design-system/button`). Кнопка «назад» в шапке появляется, если задан `onBackButtonClick`.

```tsx
import { Modal } from '@design-system/modal';
import { useState } from 'react';

export function Example() {
  const [open, setOpen] = useState(false);

  return (
    <>
      <button type='button' onClick={() => setOpen(true)}>
        Открыть
      </button>
      <Modal
        open={open}
        onClose={() => setOpen(false)}
        title='Редактирование'
        onBackButtonClick={() => setOpen(false)}
        content={<form>{/* поля */}</form>}
        footer={<div className='actions'>{/* подтверждение / отмена */}</div>}
      />
    </>
  );
}
```

### Режимы `regular`, `aggressive`, `forced`

Используйте константы `MODE` из пакета для единообразия с типами.

```tsx
import { Modal, MODE } from '@design-system/modal';
import { useState } from 'react';

export function ForcedNotice() {
  const [open, setOpen] = useState(true);

  return (
    <Modal
      mode={MODE.Forced}
      open={open}
      title='Требуется действие'
      content={<p>Закрытие только после выполнения сценария в контенте.</p>}
      onClose={() => setOpen(false)}
    />
  );
}
```

### Состояние загрузки

```tsx
import { Modal } from '@design-system/modal';

<Modal
  open={isOpen}
  onClose={handleClose}
  title='Сохранение'
  loading={isSaving}
  loadingState={<p>Кастомный текст вместо спиннера</p>}
  content={<p>Обычный контент, когда не loading</p>}
  footer={!isSaving ? <button type='button'>Сохранить</button> : undefined}
/>
```

### ModalCustom

Когда нужна своя композиция без пресетного **Modal**:

```tsx
import { ModalCustom } from '@design-system/modal';
import { useState } from 'react';

export function Example() {
  const [open, setOpen] = useState(false);

  return (
    <>
      <button type='button' onClick={() => setOpen(true)}>
        Открыть
      </button>
      <ModalCustom open={open} onClose={() => setOpen(false)} size='m'>
        <ModalCustom.Header title='Заголовок' />
        <ModalCustom.Body content={<div>Произвольный контент</div>} />
        <ModalCustom.Footer>Область действий</ModalCustom.Footer>
      </ModalCustom>
    </>
  );
}
```

### Портал и история браузера

Чтобы монтировать окно в заданный DOM-узел, передайте `container` (`HTMLElement` или CSS-селектор). Для вложенных порталов удобнее обернуть приложение в `PortalContextProvider` из `@design-system/portal-context` и не указывать `container`. Закрытие при навигации по истории — через `closeOnPopstate`.

## Accessibility

- Окно имеет `role="dialog"` и `aria-modal="true"`. При наличии `title` на **Modal** прокидывается `aria-labelledby`, связанный с заголовком в шапке. У корневого контейнера диалога задан `tabIndex={-1}`: при открытии фокус переносится на контейнер (без автофокуса на кнопки), первый **Tab** ведёт к первому tabbable; если tabbable нет, фокус остаётся на контейнере.
- Кнопка закрытия имеет `aria-label="close modal"`.
- В режиме **regular** закрытие по **Escape** и клику по затемнению; в **aggressive** / **forced** поведение согласовано с пропом `mode` (см. реализацию ModalCustom).
- Для **ModalCustom** без видимого заголовка задайте доступное имя вручную (например `aria-label` или `aria-labelledby` через пропы поддержки HTML-атрибутов).
- Изображение в шапке использует `role="img"` и `aria-label` из `image.alt`.
- **Клавиатура:** ловушка фокуса не даёт уйти с **Tab** за пределы открытого диалога; затемнение визуально отделяет контент страницы, блокировка скролла документа дополнительно снижает риск случайного взаимодействия с фоном (в том числе тач-устройства).

## Best practices

1. **Держите `open` и `onClose` снаружи** — единый источник правды (URL, store, родитель) предотвращает «залипание» окна и рассинхрон с анимациями.
2. **Режим `forced` — осознанно** — без кнопки закрытия и без Escape пользователь должен явно завершить сценарий в контенте; не злоупотребляйте для обычных диалогов.
3. **`closeOnPopstate`** — включайте, если модалка должна закрываться при навигации «назад», в одном стиле с Drawer и другими оверлеями.
4. **Футер для главных действий** — подтверждение и отмена удобно держать в `footer`, чтобы они не уезжали при прокрутке длинного тела.
5. **Тесты** — для стабильных селекторов можно использовать `TEST_IDS` из пакета.
