# Toggles

Пакет **@design-system/toggles** содержит примитивы **`Radio`**, **`Checkbox`**, **`Switch`**, **`Favourite`** и обёртку **`ToggleGroup`** с хуком **`useToggleGroup`**. Визуальные контролы строятся на скрытом нативном `<input>` (кроме состояния **`loading`**, когда инпут не монтируется), поддерживают размеры **`SIZE.XS`** / **`SIZE.S`** и общий контракт пропов на базе **`ToggleProps`**.

- **`Radio`** — взаимоисключающий выбор: `<input type="radio">`, на корне **`role="radio"`**; общий **`name`** и разные **`value`** для группы.
- **`Checkbox`** — независимое включение/выключение; **`indeterminate`** / **`indeterminateDefault`** для «частично выбрано»; корень с **`role="checkbox"`**.
- **`Switch`** — переключатель «вкл/выкл»: нативно **`type="checkbox"`**, на корне **`role="checkbox"`** (иконка галочки вместо «ползунка»); те же **`disabled`**, **`loading`**, **`size`**, что у чекбокса, **без** `indeterminate`.
- **`Favourite`** — избранное с иконкой **звезды** или **сердца** (`FAVOURITE_ICON`); под капотом **`type="checkbox"`**, **`role="checkbox"`** на корне; опционально **`onKeyUp`** и прочие пропы попадают на нативный **`<input>`** через `...`-пропы.
- **`ToggleGroup`** — контекст выбора **одного** (`SELECTION_MODE.Single`) или **нескольких** (`SELECTION_MODE.Multiple`) строковых **`value`**; **`useToggleGroup({ value })`** выдаёт **`isChecked`**, **`handleClick`** и **`multipleSelection`** для кастомных дочерних контролов (см. сторис «Toggle Group»).

## Overview

### Radio

- **Группа выбора** — несколько `Radio` с общим атрибутом **`name`** и разными **`value`** ведут себя как стандартная группа радиокнопок.
- **Семантика** — скрытый **`<input type="radio">`**, корневая обёртка с **`role="radio"`** и **`data-size`**.
- **Контролируемый режим** — **`checked`** + **`onChange(checked: boolean)`**; **неконтролируемый** — **`defaultChecked`**.
- **Состояния** — **`disabled`**, **`loading`** (индикатор загрузки вместо маркера выбора).
- **Размер** — **`size`**: `SIZE.XS` | `SIZE.S`.
- **Тесты** — **`data-test-id`** на корне; у нативного инпута — **`${dataTestId}-native-input`** (как у остальных тумблеров).

### Checkbox

- **Независимое значение** — в отличие от радио, каждый `Checkbox` управляет своим **`checked`**; для форм используйте **`name`**, **`value`**, **`id`** при необходимости.
- **Контролируемый режим** — **`checked`** + **`onChange(checked: boolean)`**; **неконтролируемый** — **`defaultChecked`**.
- **Частичный выбор** — **`indeterminate`** (контролируемо) или **`indeterminateDefault`** (начальное значение); при смене значения через UI компонент сбрасывает indeterminate в пользу явного `checked`.
- **Состояния и размер** — те же **`disabled`**, **`loading`**, **`size`**, что у `Radio`.
- **Нативный инпут** — `<input type="checkbox">` визуально скрыт, в фокусном порядке; корневой элемент с **`role="checkbox"`** и **`data-size`**. При **`loading={true}`** нативный `<input>` **не монтируется** (показывается спиннер) — учитывайте это в формах и тестах.
- **Автотесты** — задайте **`data-test-id`** на корне; у нативного инпута будет **`${dataTestId}-native-input`**.

### Switch

- **Назначение** — бинарное вкл/выкл; API совпадает с **`ToggleProps`** у чекбокса (**без** `indeterminate`).
- **Семантика** — **`<input type="checkbox">`**, корень с **`role="checkbox"`** и **`data-size`**; внутри — иконка галочки (`CheckSVG`), при **`loading`** — спиннер.
- **Состояния и размер** — те же **`disabled`**, **`loading`**, **`size`**, что у `Checkbox`; при **`loading={true}`** нативный инпут **не монтируется**.
- **Автотесты** — тот же паттерн **`data-test-id`** / **`${dataTestId}-native-input`**.

### Favourite

- **Назначение** — отметка элемента как избранного (лайк / закладка); семантика как у чекбокса: **`checked`**, **`defaultChecked`**, **`onChange`**, **`disabled`**, **`loading`**, **`size`**.
- **Иконка** — **`icon`**: `FAVOURITE_ICON.Star` или `FAVOURITE_ICON.Heart` (по умолчанию — сердце).
- **Нативный инпут** — `<input type="checkbox">`; при **`loading`** инпут не монтируется (как у `Checkbox`).
- **Корень** — **`role="checkbox"`**, **`data-icon`**, **`data-size`**, атрибуты состояния (`data-checked`, **`data-focusvisible`** и др.).
- **Клавиатура** — при необходимости **`onKeyUp`** и остальные HTML-пропы пробрасываются на **нативный `<input>`** (не на `span`).
- **Автотесты** — тот же паттерн **`data-test-id`** / **`${dataTestId}-native-input`**.

### ToggleGroup

- **Назначение** — общее состояние для набора опций с строковыми идентификаторами; дочерние элементы сами по себе **не** подключаются к контексту — используйте **`useToggleGroup({ value: 'id' })`** (или **`useToggleGroupContext`**) и вызывайте **`handleClick`** на своём UI (кнопка, карточка и т.д.). Хук отдаёт **`isChecked`**, **`handleClick`**, **`multipleSelection`** (флаг режима **multiple**).
- **Режимы** — **`selectionMode={SELECTION_MODE.Single}`** (по умолчанию): в `value` хранится **одна** строка или **`undefined`** (повторный клик по выбранному снимает выбор). **`SELECTION_MODE.Multiple`**: `value` — **массив** строк, клик по пункту переключает членство в массиве.
- **Контроль** — **`value`** + **`onChange`** или **`defaultValue`**; тип `value` / `onChange` сужается по **`selectionMode`** (об этом знает TypeScript).
- **Связь с `Radio` / `Checkbox`** — **`ToggleGroup`** не заменяет нативный **`name`** у `Radio`; это отдельный паттерн для кастомных списков опций.

## Usage

### Контролируемый режим

```tsx
import { Radio } from '@design-system/toggles';
import { useState } from 'react';

export function Example() {
  const [checked, setChecked] = useState(false);

  return (
    <Radio
      name="option"
      value="a"
      checked={checked}
      onChange={setChecked}
      aria-label="Согласие"
    />
  );
}
```

### С `inputRef`

```tsx
import { Radio } from '@design-system/toggles';
import { useRef, useEffect } from 'react';

export function Example() {
  const inputRef = useRef<HTMLInputElement>(null);

  useEffect(() => {
    inputRef.current?.focus();
  }, []);

  return <Radio name="x" value="1" inputRef={inputRef} aria-label="Фокус при монтировании" />;
}
```

### Checkbox: контролируемый режим и indeterminate

```tsx
import { Checkbox } from '@design-system/toggles';
import { useState } from 'react';

export function Example() {
  const [checked, setChecked] = useState(false);
  const [indeterminate, setIndeterminate] = useState(true);

  return (
    <Checkbox
      checked={checked}
      indeterminate={indeterminate}
      onChange={(next) => {
        setChecked(next);
        setIndeterminate(false);
      }}
      aria-label="Выбрать все"
    />
  );
}
```

### Favourite: контролируемый режим

```tsx
import { Favourite, FAVOURITE_ICON } from '@design-system/toggles';
import { useState } from 'react';

export function Example() {
  const [favourite, setFavourite] = useState(false);

  return (
    <Favourite
      icon={FAVOURITE_ICON.Heart}
      checked={favourite}
      onChange={setFavourite}
      aria-label="В избранном"
    />
  );
}
```

### Switch: контролируемый режим

```tsx
import { Switch } from '@design-system/toggles';
import { useState } from 'react';

export function Example() {
  const [on, setOn] = useState(false);

  return <Switch checked={on} onChange={setOn} aria-label="Функция включена" />;
}
```

### ToggleGroup и useToggleGroup

```tsx
import { SELECTION_MODE, ToggleGroup, useToggleGroup } from '@design-system/toggles';

function Item({ id, label }: { id: string; label: string }) {
  const { isChecked, handleClick } = useToggleGroup({ value: id });

  return (
    <button type="button" aria-pressed={isChecked} onClick={handleClick}>
      {label}
    </button>
  );
}

export function SegmentList() {
  return (
    <ToggleGroup selectionMode={SELECTION_MODE.Single} defaultValue="a">
      <Item id="a" label="А" />
      <Item id="b" label="Б" />
    </ToggleGroup>
  );
}
```

## Accessibility

### Radio

- Под капотом — нативный **`input type="radio"`** в фокусном порядке; корневая обёртка с **`role="radio"`** для кастомного UI.
- Для одиночной радиокнопки без видимой подписи задайте **`aria-label`** или **`aria-labelledby`**.
- Для группы вариантов предпочтительно оборачивать в **`<fieldset>`** с **`<legend>`** и связывать подписи через **`<label htmlFor={id}>`** и **`id`** на `Radio`.

### Checkbox

- Нативный **`input type="checkbox"`** остаётся в фокусном порядке; кликабельная область совпадает с визуальным контролом.
- При **`loading`** нативный инпут временно отсутствует в DOM — фокус и отправка формы для этого состояния должны учитываться отдельно (например, блокировка сабмита до завершения загрузки).
- Состояние **indeterminate** задаётся через DOM-свойство `indeterminate` на инпуте; озвучивание зависит от скринридера — при необходимости дополняйте **`aria-checked`** на уровне обёртки (паттерны WAI-ARIA для «mixed»).
- Для чекбокса без текстовой подписи используйте **`aria-label`**, **`aria-labelledby`** или явный **`<label>`**.

### Switch

- Нативный **`input type="checkbox"`** и **`role="checkbox"`** на корне — для скринридеров это чекбокс, а не роль `switch`; при необходимости уточняйте смысл подписью (**`aria-label`**) или связкой с **`label`**.
- При **`loading`** нативный инпут отсутствует в DOM — то же ограничение, что у `Checkbox` / `Favourite`.

### Favourite

- Семантика как у чекбокса: нативный **`input type="checkbox"`**, **`role="checkbox"`** на корне — клавиатура и скринридеры ведут себя ожидаемо при наличии **`aria-label`** / связки с **`label`**.
- При **`loading`** нативный инпут не в DOM — учитывайте то же, что для `Checkbox`.
- Вариант **`icon`** влияет только на визуал; для пользователей вспомогательных технологий опирайтесь на текстовое имя кнопки (**`aria-label`**) или видимую подпись, а не на форму иконки.
- **`onKeyUp`** и прочие переданные пропы обрабатываются на **нативном инпуте**, а не на `span`-обёртке.

### ToggleGroup

- Дочерние элементы сами не получают фокус от контекста — обеспечьте **`aria-pressed`**, **`aria-selected`** или **`role`** / подписи в вашем UI в зависимости от паттерна (кнопки-сегменты, вкладки и т.д.).
- В режиме **single** повторный выбор снимается (**`value`** может стать **`undefined`**) — заложите это в валидацию и отображение.

## Best practices

### Radio

1. **Один `name` на группу** — иначе радиокнопки не будут взаимоисключающими.
2. **Уникальные `value`** внутри группы — для корректной отправки форм и состояния.
3. **Не дублировать `defaultChecked`** у нескольких элементов с одним `name` — поведение браузера непредсказуемо; для начального выбора оставьте один `defaultChecked` или управляйте **`checked`** сами.

### Checkbox

1. **`indeterminate`** используйте для «выбрано частично» (например, заголовок колонки в таблице), **`checked`** — для полного включения; при переключении пользователем обновляйте оба флага согласованно.
2. **Не полагайтесь только на визуал «минуса»** — синхронизируйте `checked` и `indeterminate` в состоянии, чтобы нативный инпут и вспомогательные технологии совпадали.
3. В группах с логикой «выбрать все» держите состояние родителя в одном месте и прокидывайте **`checked`** / **`indeterminate`** в заголовочный `Checkbox`.
4. В **`loading`** не ждите значения из поля формы — инпут не смонтирован; для Storybook и ссылок с `args` в Playground объявляйте **`id`** и **`name`** в `args` сторис, иначе они не подставятся из URL.

### Switch

1. Используйте для настроек «да/нет», где не нужен **indeterminate**; для трёхсостоятельных списков — **`Checkbox`**.
2. Учитывайте, что визуал — тумблер с галочкой, а роль остаётся **чекбоксом**; формулируйте **`aria-label`** как вкл/выкл или согласованный текст.
3. Те же правила **`loading`** и форм, что у **`Checkbox`**.

### Favourite

1. Задавайте **`name`** / **`value`**, если компонент участвует в отправке формы или в группе переключателей.
2. Выбирайте **`icon`** (звезда или сердце) в соответствии с продуктовой терминологией («избранное», «лайк» и т.д.) и согласуйте подпись **`aria-label`** с этим смыслом.
3. В **`loading`** не рассчитывайте на значение нативного поля — инпут отсутствует в DOM, как у `Checkbox`.

### ToggleGroup

1. Стабильные строковые **`value`** для элементов списка — они и есть ключ состояния в контексте.
2. Для **multiple** держите **`value`** как массив и нормализуйте его в родителе; для **single** допускайте **`undefined`** после снятия выбора.
3. Не смешивайте **`ToggleGroup`** с нативной отправкой **`Radio`** по **`name`** без явной синхронизации состояния — это разные механизмы.
