# Breadcrumbs

Навигационная цепочка «хлебных крошек»: показывает путь до текущей страницы. При узком контейнере сама подбирает отображение — полный текст, короткий ярлык (`shortLabel`), многоточие или свёртка средних пунктов в выпадающий список.

**Version:** `{frontmatter.version}`

Поддерживает:

- **Адаптивная вёрстка** — измерение доступной ширины и выбор оптимальной конфигурации цепочки
- **Элементы** — `href`, `onClick` или статичный текст для текущей страницы; опциональная иконка у пункта
- **Размеры** — `xs` и `s`
- **Разделитель** — настраиваемая строка между пунктами (по умолчанию символ `›` из константы пакета)
- **Первый пункт только иконкой** — `firstItemIconOnly` при наличии `icon` у первого элемента
- **Некликабельный последний шаг** — `inactiveLastItem` отключает переход по последнему пункту, даже если заданы `href` / `onClick`
- Figma: [Snack UI Kit](https://www.figma.com/design/aNPU3MHwRJiEwbk5F82zux/Snack-Ui-Kit-variables?node-id=7422-10279&p=f&m=dev)

Пакет также экспортирует тип `Item` и функцию `setNonce` (из `@snack-uikit/list`) — для nonce при строгой CSP, если используется выпадающий список свёрнутых пунктов.

## Overview

Разметка: обёртка `<nav>`, внутри список `<ul>` / `<li>`. Кликабельные пункты рендерятся как `<a>` (при `href`) или `<button type="button">` (при `onClick`). Пункт без `href` и без `onClick` — текущая страница: текст в `<div>` с признаком текущего шага (`data-current`).

Для узких контейнеров компонент строит несколько вариантов цепочки и выбирает подходящий. Полезно задавать осмысленные `shortLabel` у длинных названий — так средние уровни читаются лучше в режиме сокращённых подписей.

## Special cases

### Короткие подписи при нехватке места

Задавайте для длинных названий `shortLabel`, чтобы цепочка оставалась понятной в сжатом режиме.

```tsx
import { Breadcrumbs } from '@design-system/breadcrumbs';

const items = [
  { id: '1', label: 'Очень длинное название раздела', shortLabel: 'Раздел', href: '#' },
  { id: '2', label: 'Текущая' },
];

export function Example() {
  return <Breadcrumbs items={items} />;
}
```

### Некликабельный последний сегмент

Удобно, когда последний пункт совпадает с заголовком страницы, но вы всё равно передаёте `href` из данных:

```tsx
<Breadcrumbs
  inactiveLastItem
  items={[
    { id: '1', label: 'Каталог', href: '/catalog' },
    { id: '2', label: 'Товар', href: '/catalog/item-1' },
  ]}
/>
```

### CSP и `setNonce`

Если для inline-стилей выпадающего списка (свёрнутые пункты) нужен nonce:

```tsx
import { Breadcrumbs, setNonce } from '@design-system/breadcrumbs';

setNonce('your-nonce-value');
```

### Тип `Item`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор пункта |
| `label` | `string` | Основной текст |
| `shortLabel` | `string` | Короткий текст для узкой ширины |
| `icon` | `JSXElementConstructor<{ size: number }>` | Опциональная иконка |
| `href` | `string` | Ссылка; с `<a>` |
| `onClick` | обработчик мыши | Действие; с `<button>` (может сочетаться с `href` на `<a>`) |

Через `WithSupportProps` поддерживаются `data-test-id`, `aria-*` и прочие пропы поддержки на корневой обёртке (`<nav>`).

## Accessibility

- Семантика навигации: корень — `<nav>`, пункты — элементы списка `<li>`.
- Текущий шаг без ссылки не попадает в таб-ордер как отдельная ссылка; интерактивные крошки остаются фокусируемыми.
- Для режима «только иконка» у первого пункта задаётся `aria-label` из `label`, чтобы имя было доступно вспомогательным технологиям.
- В свёрнутом виде средние пункты доступны через кнопку раскрытия и выпадающий список (клавиатура и скринридеры зависят от поведения `@snack-uikit/list`).

## Best practices

1. **Уникальные `id`** — стабильные ключи для внутренней логики и тестов.
2. **`shortLabel`** — задавайте для длинных названий, чтобы цепочка оставалась понятной в сжатом режиме.
3. **Текущая страница** — без `href`/`onClick`; не дублируйте заголовок страницы сомнительными ссылками на «саму себя», если это не нужно для SEO.
4. **`inactiveLastItem`** — когда последний элемент приходит из API с URL, но в UI он должен быть только текстом.
5. **Ширина контейнера** — крошки реагируют на ширину родителя; избегайте обрезки без учёта отступов макета.
6. **Разделитель** — держите строку короткой и нейтральной для скринридеров (визуальный символ, а не дублирование всей навигации текстом).
