# Figma variables

`@ds/figma-variables` — Figma design tokens (CSS custom properties, SCSS modules, TS) для дизайн-системы.

Пакет содержит только генерируемые артефакты: значения токенов экспортируются из Figma в `tokens/`, собираются style-dictionary и попадают в `build/`. JS-логики в нём нет — компоненты подключают SCSS-модули напрямую, приложение один раз импортирует runtime-слой с CSS-переменными.

## Установка

```bash
pnpm add @ds/figma-variables
```

## Состав

- `build/css/tokens.css` — runtime-слой: объявляет `:root { --sn-*: … }`
- `build/scss/styles/styles.module.scss` — общие токены темы и примитивы
- `build/scss/components/<name>.module.scss` — токены анатомии конкретного компонента
- `build/ts/styles.js`, `build/ts/styles.d.ts` — те же токены как TS-объект

## Использование

Runtime-слой подключается один раз в точке входа приложения. Без него значения `var(--sn-*)` пустые:

```ts
import '@ds/figma-variables/build/css/tokens.css';
```

Стили компонентов ссылаются на токены через SCSS-модули:

```scss
@use '@ds/figma-variables/build/scss/styles/styles.module' as base;

.root {
  outline: base.$sn-primitive-strokeWeight-strokeSemiBold solid base.$sn-theme-color-available-complementary;
}
```

Токены анатомии отдельного компонента лежат в `components/`:

```scss
@use '@ds/figma-variables/build/scss/components/table.module' as table;
```

## Регенерация

Собранный `build/` закоммичен, поэтому после клонирования всё работает сразу. Пересобирать нужно при изменении `tokens/`, из корня репозитория:

```bash
pnpm build:tokens
```

Команда собирает токены, обновляет карты `@ds/figma-selected-block` и в конце запускает проверку ссылок на токены (см. ниже). Если проверка находит проблемы, команда завершается с кодом 1. Результат коммитится вместе с изменениями в `tokens/`.

В CI это делает ручная джоба `build-tokens` в MR. При ошибке проверки джоба завершается с ошибкой, и пересобранный `build/` не коммитится.

## Проверка ссылок на токены

SCSS-переменные этого пакета при сборке компонента превращаются в цепочки `var(--sn-a, var(--sn-b, value))` и попадают в `dist` компонента. Значения токенов приходят в рантайме из `tokens.css`, поэтому смена значения не требует пересборки компонентов. Пересборка нужна, когда токен переименован или удалён: lerna не переиздаёт пакет, в коде которого ничего не менялось, и в registry остаётся сборка со старыми именами.

`pnpm check:token-refs` находит такие пакеты. Скрипт собирает все `var(--sn-*)` из `dist` пакетов и сверяет их с токенами, объявленными в `build/css`. Токены, которые объявляет сам пакет (локальные переменные, рантайм-токены `@ds/theme`), не считаются пропавшими.

```bash
pnpm check:token-refs                          # последние версии из registry — то, что установлено у потребителей
pnpm check:token-refs --local                  # локальные packages/*/dist, после pnpm build:packages
pnpm check:token-refs --pkg typography,button  # только указанные пакеты (имя папки в packages/)
pnpm check:token-refs --verbose                # все пропавшие токены, а не первые пять
```

При проверке по registry пакеты, которые попадут в следующий релиз (изменённые с последнего тега и их dependents, тот же набор, что публикует пайплайн), ошибкой не считаются: при публикации они пересоберутся на текущих токенах. В отчёте они отмечены `↻`.

Остальные пакеты со ссылками на несуществующие токены выводятся списком, и скрипт завершается с кодом 1:

```text
✗ Нужно выпустить пакеты: 1 — опубликованная сборка ссылается на удалённые токены
  • @cloud-ru/ds-typography@1.0.0 (packages/typography)
    устарело в fallback, на отрисовку не влияет, 10: --sn-primitive-font-lineHeight-by14, … и ещё 7

Как исправить: добавь в src/ каждого пакета незначащую правку (например, комментарий) и закоммить её с префиксом fix — lerna включит пакеты в следующий релиз.
  git commit -m "fix(<задача>): rebuild on current figma-variables tokens"
Правки в *.md, *.mdx, CHANGELOG.md, stories/, __test__/, __tests__/, demos/, docs/ не подходят — lerna их не учитывает.
```

У каждого пакета указан вид устаревших ссылок:

- **сломано** — первая ссылка цепочки (primary). Браузер читает её всегда, поэтому пропавший токен ломает стиль уже сейчас.
- **устарело в fallback** — ссылка внутри запасного значения. Сборка устарела, но пока токен из начала цепочки существует, на отрисовку это не влияет.

Под списком скрипт выводит рекомендацию: чтобы пакет вышел в следующем релизе, в него добавляется незначащая правка (например, комментарий в `src/`) и коммитится с префиксом `fix`:

```bash
git commit -m "fix(<задача>): rebuild on current figma-variables tokens"
```

lerna выпускает пакет, только если изменены файлы вне `ignoreChanges` из `lerna.json`. Правки в `*.md`, `stories/`, `docs/`, `demos/`, `__test__/` и `__tests__/` выпуск не запускают — скрипт выводит актуальный список этих путей в отчёте. Если у пакета есть ссылки с пометкой **сломано** и он использует токен в исходниках напрямую, одна пересборка ссылку не исправит — сначала нужно заменить токен в коде пакета.

`--local` проверяет то, что будет опубликовано из текущих исходников. Если пакет есть в отчёте `--local`, но исходники ссылаются только на существующие токены, значит его локальный `dist` собран до обновления токенов и пакет нужно пересобрать.
